# Internationalization (i18n)

## Library

[typesafe-i18n](https://github.com/ivanhofer/typesafe-i18n) v5.27.1 — fully typed, Svelte store-based.

## Supported Locales

| Code | Language |
|------|----------|
| `en-US` | English (default) |
| `vi-VN` | Vietnamese |

## File Structure

```
src/i18n/
  en-US/index.ts       ← base locale, drives all TypeScript types
  vi-VN/index.ts       ← Vietnamese translations
  i18n-types.ts        ← Translation, TranslationFunctions, Locales types
  i18n-util.ts         ← exports { LL, locale, setLocale }
```

## Locale Resolution (priority order)

1. `Accept-Language` header → resolved in `hooks.server.ts` → stored in `locals.lang`
2. Partial match (e.g. `vi` → `vi-VN`)
3. Fallback: `en-US`
4. `+layout.server.ts` passes `locals.lang` to client → `+layout.svelte` calls `setLocale(data.lang)` on mount

## Usage in Svelte components

```svelte
<script lang="ts">
  import { LL, setLocale, locale } from '$i18n/i18n-util';
  import type { Locales } from '$i18n/i18n-util';
</script>

<!-- Simple key -->
{$LL.auth.login_success()}

<!-- With params -->
{$LL.admin.created({ resource: 'Client' })}
{$LL.validation.required_field({ field: 'Email' })}

<!-- Lang switcher -->
<button class:active={$locale === 'en-US'} onclick={() => setLocale('en-US' as Locales)}>EN</button>
<button class:active={$locale === 'vi-VN'} onclick={() => setLocale('vi-VN' as Locales)}>VI</button>
```

## Rules — MUST follow when adding translations

1. **Always add to both locales at the same time.** Never add a key to `en-US/index.ts` without also adding it to `vi-VN/index.ts`.

2. **Always update `i18n-types.ts`.** When adding a new key:
   - Add the field to the `Translation` type
   - Add the corresponding function signature to the `TranslationFunctions` type
   - For keys with params use `RequiredParams<'paramName'>` in `Translation` and `(arg: { paramName: string }) => LocalizedString` in `TranslationFunctions`

3. **Always update this doc.** Add the new key(s) to the reference table above.

4. **Param syntax in locale files** uses `{name:string}` — e.g. `'{field:string} is required'`.

5. **Never use bare string literals** for UI text in Svelte components. Always go through `$LL`.

## Adding a New Key — Checklist

- [ ] Add key + English value to `src/i18n/en-US/index.ts`
- [ ] Add key + Vietnamese value to `src/i18n/vi-VN/index.ts`
- [ ] Add field to `Translation` type in `src/i18n/i18n-types.ts`
- [ ] Add function signature to `TranslationFunctions` type in `src/i18n/i18n-types.ts`
- [ ] Use `$LL.section.key()` in the Svelte component
- [ ] Update this doc's reference table

## Adding a New Locale

1. Create `src/i18n/{locale-code}/index.ts` implementing `Translation`
2. Add the locale to `Locales` union in `src/i18n/i18n-types.ts`
3. Import and add it to the `translations` map in `src/i18n/i18n-util.ts`
4. Add the locale code to `SUPPORTED_LOCALES` in `src/hooks.server.ts`
